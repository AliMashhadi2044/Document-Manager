
# ۱۰ — برنامه امنیت

## ۱. احراز هویت و نشست

تصمیم: **نشست سروری با کوکی**، نه JWT در مرورگر ([ADR-0004](adr/ADR-0004-session-cookie-auth.md)).

| موضوع | پیاده‌سازی |
|---|---|
| هش رمز | Argon2id با پارامترهای توصیه‌شده OWASP |
| کوکی نشست | `HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/`, بدون `Domain` عمومی |
| ذخیره توکن | **هش** توکن در `sessions`، نه خود توکن |
| انقضا | انقضای مطلق (مثلاً ۱۲ ساعت) + انقضای بی‌تحرکی (مثلاً ۳۰ دقیقه)، هر دو قابل تنظیم |
| خروج | ابطال سروری ردیف نشست (نه فقط حذف کوکی)؛ «خروج از همه دستگاه‌ها» موجود است |
| چرخش | شناسه نشست پس از ورود موفق بازتولید می‌شود (ضد session fixation) |
| محدودیت تلاش | شمارش خطا در `users.failed_login_count` + قفل زمانی + محدودیت نرخ بر اساس IP |
| رویدادهای امنیتی | ورود موفق/ناموفق، قفل، خروج، تغییر رمز، تغییر نقش در `security_events` |
| localStorage | **هیچ توکن یا داده حساسی** در localStorage یا sessionStorage نگه داشته نمی‌شود |

### CSRF

چون احراز هویت کوکی‌محور است، محافظت CSRF **الزامی** است:

- الگوی double-submit: یک توکن CSRF در کوکی **غیر HttpOnly** و همان مقدار در هدر
  `X-CSRF-Token`؛ سرور تطبیق را بررسی می‌کند و مقدار را با نشست گره می‌زند.
- اجبار برای همه متدهای غیرامن (`POST`, `PUT`, `PATCH`, `DELETE`).
- `SameSite=Lax` لایه دوم است، نه تنها لایه.
- بررسی هدر `Origin`/`Referer` برای درخواست‌های حساس.

## ۲. مجوز و IDOR

سه لایه مستقل، شرح کامل در [06-roles-permissions.md](06-roles-permissions.md):
Guard مجوز → شرط کوئری دامنه دسترسی → قاعده وضعیت و فهرست سفید فیلد.

ضد IDOR:

- شناسه‌ها `uuid v7` هستند، نه عدد ترتیبی.
- دامنه دسترسی به‌صورت **شرط `WHERE`** اعمال می‌شود، نه بررسی پس از خواندن.
- خارج از دامنه ← `404` (نه `403`) تا وجود رکورد لو نرود.
- تست خودکار: هر endpoint با شناسه معتبر خارج از دامنه هر نقش آزمون می‌شود.

## ۳. اعتبارسنجی ورودی

- Zod در یک pipe سراسری؛ هیچ controller بدون schema.
- `strict()` روی objectها: فیلد ناشناخته **رد** می‌شود، نه نادیده گرفته.
- سقف اندازه بدنه درخواست (پیش‌فرض ۱ مگابایت برای JSON، جدا برای آپلود فایل).
- سقف طول رشته‌ها (مثلاً شماره نیاز حداکثر ۵۰ نویسه طبق §۹).
- SQL Injection: تنها مسیر دسترسی Prisma با پارامتر؛ SQL خام فقط در migration و در
  صورت نیاز با `Prisma.sql` پارامتری — رشته‌سازی کوئری ممنوع و با قاعده lint مسدود است.

## ۴. XSS و CSP

- React به‌صورت پیش‌فرض escape می‌کند؛ `dangerouslySetInnerHTML` با قاعده ESLint **ممنوع**.
- هدرهای امنیتی (helmet + تنظیم دستی):

```
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self';
  img-src 'self' blob: data:; font-src 'self'; object-src 'none';
  frame-ancestors 'none'; base-uri 'self'; form-action 'self'
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: same-origin
Strict-Transport-Security: max-age=31536000; includeSubDomains
Permissions-Policy: camera=(), microphone=(), geolocation=()
```

- پیش‌نمایش PDF با pdf.js و worker محلی؛ **هیچ** `<iframe>` به فایل آپلودی.
- پیش‌نمایش SVG و HTML **پشتیبانی نمی‌شود** (نوع فایل در allowlist نیست).

## ۵. فایل‌ها

شرح کامل: [12-file-storage-policy.md](12-file-storage-policy.md). خلاصه کنترل‌ها:
allowlist نوع، بررسی magic byte، سقف حجم و تعداد، نام‌گذاری سروری، ذخیره خارج از مسیر
اجرایی، دانلود مجوزدار با `Content-Disposition: attachment`، ضد Path Traversal.

## ۶. محدودیت نرخ و منابع

| مسیر | محدودیت |
|---|---|
| `POST /auth/login` | بر اساس IP و نام کاربری، با تأخیر پیش‌رونده |
| کل API | محدودیت عمومی هر کاربر در دقیقه |
| آپلود فایل | تعداد و حجم در بازه زمانی |
| تولید PDF | حداکثر ۲ همزمان، timeout ۶۰ ثانیه |
| اجرای گزارش | صف با سقف طول؛ گزارش حجیم به پس‌زمینه |

## ۷. مدیریت secret و تنظیمات

- هیچ secret در مخزن، در کد Frontend یا در `.env.example`.
- اعتبارسنجی متغیرهای محیطی با Zod در bootstrap؛ **fail fast** در صورت نقص، بدون
  پیش‌فرض ناامن.
- کلیدهای object storage با کمترین دسترسی لازم (نوشتن/خواندن فقط همان bucket).
- `npm audit` و بررسی وابستگی‌ها در CI؛ به‌روزرسانی امنیتی بخشی از هر فاز.

## ۸. مدیریت خطا و log

- پاسخ خطا ساختاریافته با پیام فارسی قابل نمایش + `traceId`.
- **هرگز** stack trace، نام جدول، کوئری یا پیام دیتابیس به کاربر نمی‌رسد.
- log با `pino` و redact اجباری برای: `password`, `passwordHash`, `token`, `cookie`,
  `authorization`, `iban`, `nationalId`, `economicCode`, `csrf`.
- داده حساس در **URL و query string** قرار نمی‌گیرد (فیلترها در صورت نیاز با `POST`).
- `audit_logs` فقط فیلدهای لازم را نگه می‌دارد؛ دسترسی به تاریخچه خودش مجوزدار است
  (`audit:read`).

## ۹. CORS

- در Production رابط وب از **همان origin** سرو می‌شود → CORS لازم نیست و بسته می‌ماند.
- در توسعه، `origin` فقط `http://localhost:5173` با `credentials: true`.
- هیچ‌گاه `origin: '*'` همراه با `credentials`.
