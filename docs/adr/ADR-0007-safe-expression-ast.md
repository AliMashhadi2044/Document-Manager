
# ADR-0007 — AST امن برای شرط و محاسبه گزارش

**وضعیت:** پذیرفته · **تاریخ:** فاز ۰

## زمینه

طراح گزارش باید به کاربر اجازه دهد شرط و محاسبه تعریف کند («اگر فروشنده حقوقی است نام
نماینده نمایش داده شود»، «جمع مالیات»). پرامپت صریحاً اجرای `eval`، `Function`،
JavaScript دلخواه، SQL دلخواه و دسترسی مستقیم به دیتابیس از داخل قالب را **ممنوع**
می‌کند. این بزرگ‌ترین سطح حمله پروژه است (ریسک R4 و R5): قالب، داده‌ای است که کاربر
می‌سازد و سرور آن را اجرا می‌کند.

## تصمیم

یک **AST داده‌ای بسته**: شرط و محاسبه به‌صورت ساختار JSON با مجموعه **محدود و شمارش‌شده**
عملگرها تعریف می‌شوند، با Zod اعتبارسنجی و با یک مفسر اختصاصی ارزیابی می‌شوند.

عملگرهای مجاز:
`const`, `var`, `agg(sum|count|min|max|avg)`, `arith(add|sub|mul|divRound)`,
`concat`, `if`, `fmt` · شرط‌ها: `cmp`, `in`, `empty`, `and`, `or`, `not`.
همین و نه بیشتر.

محدودیت‌ها: عمق ≤ ۲۰ · گره ≤ ۵٬۰۰۰ · ردیف ≤ ۵۰٬۰۰۰ · timeout ۵ ثانیه ·
بدون حلقه و بازگشت (AST درخت است، نه گراف).

## دلایل

- **سطح حمله صفر برای اجرای کد.** هیچ رشته‌ای به مفسر JavaScript نمی‌رسد. حتی یک قالب
  کاملاً مخرب، در بدترین حالت یک AST نامعتبر است که در اعتبارسنجی رد می‌شود.
- **کنترل دسترسی ساختاری.** `var.path` باید در Data Dictionary وجود داشته باشد و
  مجوزش با کاربر **اجراکننده** سنجیده می‌شود. هیچ مسیر دیگری برای رسیدن به داده نیست.
- **تایپ‌پذیری.** `mul` روی `text` در زمان **ذخیره** رد می‌شود، نه در زمان اجرا.
- **سازگاری مالی.** `divRound` از **همان** `divRoundHalfUp` پروژه استفاده می‌کند، پس
  محاسبه گزارش با محاسبه سند واگرا نمی‌شود (ریسک R1).
- **قابل ساخت در UI.** چون ساختار داده است، سازنده شرط بصری مستقیم روی آن می‌نشیند و
  نیازی به parser زبان نیست.

## جایگزین‌های رد‌شده

| جایگزین | دلیل رد |
|---|---|
| `eval` یا `new Function` | اجرای کد دلخواه سمت سرور — ممنوعیت صریح پرامپت |
| sandbox مانند `vm2` یا `isolated-vm` | سابقه فرار از sandbox؛ پیچیدگی و وابستگی سنگین برای نیازی که AST حل می‌کند |
| موتور قالب مثل Handlebars با helper | helperها به‌سرعت به اجرای منطق دلخواه می‌رسند؛ مرز نگه داشتنش دشوار است |
| زبان مخصوص (DSL) با parser رشته‌ای | نیاز به parser، گرامر و پیام خطا؛ AST ساختارمند همان قدرت را بدون parser می‌دهد |
| SQL پارامتری تولیدشده از قالب | مسیر تزریق و نشت داده؛ خلاف جداسازی لایه ۳ و ۴ |

## پیامدها

- قدرت بیان **محدود** است؛ هر نیاز جدید (مثلاً تابع رشته‌ای) یک عملگر جدید در AST
  می‌خواهد که باید بازبینی و تست شود. این محدودیت **عمدی** است.
- `schemaVersion` روی قالب لازم است تا افزودن عملگر، قالب‌های قدیمی را نشکند.
- تست‌های اجباری: هر عملگر با نوع درست و نادرست · `var` ناشناخته → رد ·
  عمق و تعداد گره بیش از حد → رد · داده حاوی `<script>` در خروجی escape شود.
