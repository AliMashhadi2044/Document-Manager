
# ADR-0003 — مبالغ به‌صورت BIGINT ریال و رشته عددی در API

**وضعیت:** پذیرفته · **تاریخ:** فاز ۰

## زمینه

واحد تمام مبالغ ریال است و ریال کسر ندارد. اما مبالغ ریالی **بزرگ** می‌شوند: یک سند
چند میلیارد ریالی عادی است و جمع سالانه می‌تواند از محدوده عدد صحیح امن JavaScript
(`2^53 − 1 ≈ 9.007 × 10^15`) عبور کند. استفاده از `number` در هر لایه به از دست رفتن
خاموش دقت منجر می‌شود — بدترین نوع باگ مالی، چون خطا نمی‌دهد.

## تصمیم

| لایه | نوع |
|---|---|
| PostgreSQL | `BIGINT` (ریال صحیح) |
| TypeScript | `bigint` با برند `Money` |
| مرز JSON (API) | **رشته عددی** مثل `"125000000"` |
| نرخ درصد | `INTEGER` basis point (۹٪ = `900`) |
| تعداد / مقدار | `NUMERIC(18,3)` در DB، رشته در API، `bigint` مقیاس هزارم در TS |

یک `BigIntSerializerInterceptor` سراسری هر `bigint` را در پاسخ به رشته تبدیل می‌کند و
Zod schemaهای مشترک آن را در کلاینت دوباره به `bigint` می‌خوانند.

## دلایل

- **کسر ریال وجود ندارد**، پس نیازی به decimal نیست و `bigint` بومی کافی است:
  بدون وابستگی، بدون سرریز، با عملگرهای دقیق.
- نرخ درصد به‌صورت basis point صحیح، اعشار را از محاسبات **حذف** می‌کند؛ ۹٫۵٪ می‌شود
  `950` و هیچ‌جا عدد شکسته نگه داشته نمی‌شود.
- رشته در مرز JSON تنها راه مطمئن است: `JSON.stringify` روی `bigint` خطا می‌دهد و
  `JSON.parse` روی عدد بزرگ دقت را خاموشانه از بین می‌برد.

## جایگزین‌های رد‌شده

| جایگزین | دلیل رد |
|---|---|
| `number` در TypeScript | از دست رفتن خاموش دقت بالای ۲⁵³ — غیرقابل قبول |
| `NUMERIC` در دیتابیس | پیچیدگی و کندی بی‌دلیل برای مقداری که کسر ندارد |
| `decimal.js` یا `big.js` | وابستگی و API اضافه، بدون مزیت برای مقدار صحیح |
| ذخیره به تومان | خلاف تصمیم قطعی D6 و منبع خطای تبدیل |
| `number` در API با فرض «مبالغ ما کوچک‌اند» | فرض شکننده؛ جمع‌های تجمیعی آن را نقض می‌کنند |

## پیامدها

- کد باید `bigint` را جدی بگیرد: `1n` به‌جای `1`، بدون اختلاط با `number` در عملگرها.
- قاعده ESLint `Number(`، `parseInt(`، `parseFloat(` و `+x` را روی مقادیر برند `Money`
  مسدود می‌کند.
- کامپوننت `CurrencyInput` مقدار را به‌صورت **رشته رقمی** نگه می‌دارد و هرگز
  `valueAsNumber` نمی‌خواند.
- Excel: مقادیر فراتر از محدوده امن عدد Excel به‌صورت متن با نشان هشدار نوشته می‌شوند،
  نه با دقت از دست‌رفته.
- **تست اجباری:** مبلغ `9007199254740993` از فرم تا گزارش، بیت‌به‌بیت یکسان بماند.

## معیار بازنگری

اگر روزی واحد مالی دوم (ارز) لازم شود، این ADR با افزودن `currency` و جابه‌جایی به یک
نوع مرکب (`{ amount: bigint, currency: string }`) بازنگری می‌شود — نه با تغییر به `number`.
