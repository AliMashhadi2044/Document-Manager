
# ADR-0011 — object storage سازگار با S3 برای فایل‌ها

**وضعیت:** پذیرفته · **تاریخ:** فاز ۰

## زمینه

اسکن اسناد بایگانی و خروجی‌های تولیدشده (PDF/Excel) باید ذخیره شوند. الزامات پرامپت:
فضای ذخیره‌سازی **خصوصی**، پشتیبانی از S3-compatible در صورت امکان، راهکار مناسب برای
محیط توسعه، و اینکه ذخیره فایل باعث **خارج شدن فراداده از کنترل تراکنش و دسترسی نشود**.

## تصمیم

API سازگار با S3 از طریق `@aws-sdk/client-s3`، با یک لایه انتزاع نازک `StorageService`:

| محیط | پیاده‌سازی |
|---|---|
| توسعه و تست | MinIO در Docker Compose |
| Production | **MinIO در Docker** — تأییدشده با پاسخ Q12 |

**به‌روزرسانی پس از Q12:** سازمان object storage موجود **ندارد** و مبنای استقرار
**Docker** است (سرور پیشنهادی: لینوکس). بنابراین MinIO در هر دو محیط اجرا می‌شود و
تفاوت توسعه و production فقط در endpoint، credential و سیاست نگهداری است. این دقیقاً
همان مزیتی است که این ADR به‌دنبالش بود.

فراداده فایل در `attachments` در PostgreSQL، در **همان تراکنش** عملیات مربوطه.

## دلایل

- **یک API، هر دو محیط.** کد توسعه و production یکی است؛ تفاوت فقط endpoint و
  credential است. این «کار می‌کند روی لپ‌تاپ من» را حذف می‌کند.
- **خصوصی بودن.** bucket خصوصی، کلید شیء سروری و بدون نام کاربر، سرو فقط از endpoint
  مجوزدار برنامه. هیچ آدرس قابل حدس و هیچ دسترسی عمومی.
- **خروج از فایل‌سیستم برنامه.** فایل در مسیر اجرایی وب‌سرور نیست، پس «اجرای فایل
  بارگذاری‌شده» و Path Traversal ساختاراً منتفی‌اند.
- **مقیاس و backup.** پشتیبان‌گیری فایل‌ها مستقل از دیسک سرور برنامه است.

## جایگزین‌های رد‌شده

| جایگزین | دلیل رد |
|---|---|
| ذخیره در فایل‌سیستم محلی | ریسک Path Traversal و اجرا؛ backup و چندنمونه‌ای شدن دشوار |
| ذخیره در دیتابیس (`bytea` یا Large Object) | تورم دیتابیس، کندی backup و بازیابی، فشار حافظه در استریم |
| فضای ابری عمومی | خلاف الزام «عدم وابستگی غیرضروری به سرویس خارجی» برای عملکرد اصلی |
| فایل‌سیستم شبکه‌ای (SMB/NFS) | مدیریت مجوز و قفل پیچیده‌تر؛ API یکپارچه ندارد |

## پیامدها

- یک سرویس بیشتر در Docker Compose توسعه (MinIO) — هزینه کم، سود زیاد.
- **قاعده دو مرحله‌ای:** رکورد `PENDING` → آپلود و اعتبارسنجی → `READY`. job پاک‌سازی
  رکوردهای `PENDING` کهنه و اشیاء بی‌رکورد را حذف می‌کند، تا فایل بی‌صاحب نماند.
- دانلود از endpoint برنامه استریم می‌شود (نه presigned URL پیش‌فرض)، چون مجوز و
  دامنه دسترسی نقش باید در لحظه بررسی شود و دانلود باید در audit log بنشیند.
- backup باید **هر دو** (دیتابیس و object storage) را پوشش دهد و نقطه زمانی آن‌ها
  هم‌راستا باشد؛ سند بدون اسکنش بی‌ارزش است.

## معیار بازنگری

تصمیم با پاسخ Q12 تثبیت شد و بازنگری فوری لازم ندارد. اگر در آینده سازمان یک سرویس
S3-compatible مرکزی راه‌اندازی کند، مهاجرت فقط تغییر endpoint و credential است و
نیازی به تغییر کد ندارد — چون `StorageService` همان API را مصرف می‌کند.
